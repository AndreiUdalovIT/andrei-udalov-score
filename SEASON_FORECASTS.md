# Сезонный прогноз

Прогноз поддерживает пять национальных лиг и Лигу чемпионов с общим этапом на 36 команд. Состав участников, формат и границы зон берутся из [сезонной конфигурации](src/lib/config/competition-seasons.ts).

## Данные и расчёт

- Сервер берёт последний официальный снимок таблицы и состояния матчей, сохранённые до общего времени среза. Сыгранные матчи остаются фиксированными. Снятие или добавление очков в национальных лигах сохраняется из официальной таблицы.
- Оставшиеся матчи моделируются по Пуассону с фиксированными на момент среза интенсивностями голов. Для каждой лиги рассчитываются средние очки, эмпирический интервал между 10-м и 90-м процентилями, распределение мест и вероятность попадания в каждую настроенную зону. Кубковые путёвки и особые сезонные квоты учитываются в пределах сезонной конфигурации.
- По умолчанию сервер делает 10 000 прогонов. В `season_forecasts` хранятся результат, входной снимок, версия модели, время среза и расчёта, `seed` и число прогонов. Повтор расчёта с тем же снимком, `seed` и версией алгоритмов воспроизводит результат.
- Страница выбирает самый свежий по времени среза прогноз текущего сезона. «Пересчитать» передаёт тот же снимок и новый `seed` в браузерный Worker. Общий срез виден над таблицей. Локальный результат появляется в отдельной колонке и существует до ухода со страницы или нового пересчёта.

## Равенство очков

- **АПЛ.** Разница и число голов предшествуют личным встречам. Личные встречи применяются, когда группа пересекает границу чемпионства или настроенной зоны. Если группа не пересекает решающую границу, могут сохраняться общие места. Распределение учитывает такое место по началу диапазона и отдельно хранит сам диапазон. При решающем равенстве расчёт сохраняет очки и возможный диапазон мест команды во всех прогонах. Нижняя граница вероятности места или зоны учитывает определившиеся исходы. Верхняя включает прогоны, где событие возможно после стыка или решения лиги. Страница показывает диапазоны для затронутых команд отдельно для опубликованного и локального расчёта.
- **Бундеслига.** После разницы и числа голов для двух клубов сравниваются разница в личных встречах, выездные голы в них и затем все выездные голы. Если равенство сохраняется или на исходных критериях равны три клуба и больше, модель оставляет результат открытым.
- **Ла Лига.** Модель сравнивает личные встречи, затем разницу и число голов за сезон. Для группы из трёх клубов и больше сначала учитываются очки в личных встречах. После разделения группы правила применяются заново к оставшимся равным клубам. Необходимый итоговый показатель Fair Play передаётся отдельно.
- **Лига 1.** После очков и общей разницы голов применяются личные встречи и критерии выбранного сезона. Начиная с 2025/26 до дисциплинарных очков сравниваются голы, победы и выездные победы. Жребий моделируется только после исчерпания всех критериев, включая итоговую дисциплину, и только для сезонов, где жребий предусмотрен.
- **Серия А.** При равенстве очков применяется мини-таблица личных встреч, затем общие разница и число голов. Модель поддерживает жребий и предусмотренные сезоном матчи за титул и за сохранение места. Для нужного матча требуются параметры конкретной пары. В 2026/27 требуется также знать, относится ли к этой паре исключение для финалистов турниров УЕФА.

В остальных лигах отсутствующий критерий или обязательный стык без входных данных останавливает расчёт. Автоматический `full sync` передаёт официальную таблицу и историю матчей. Итоговые Fair Play, дисциплинарные очки и параметры специальных стыков он пока сам не загружает.

## Лига чемпионов

Модель ранжирует клубы общего этапа по очкам, разнице голов, голам, выездным голам, победам и выездным победам, затем по совокупным показателям соперников. При необходимости используются итоговые дисциплинарные очки и клубный коэффициент. Если сравнение зависит от отсутствующих данных, расчёт останавливается на определении посева.

До жеребьёвки модель выбирает среди допустимых пар и вариантов порядка игр. Вероятность прохода считается по всем завершённым сценариям. В двухматчевых парах используется общий счёт без преимущества выездного гола. Для ещё не сыгранного дополнительного времени берётся треть интенсивности за 90 минут. Вероятность победы по пенальти принимается равной 50% для каждой команды. В финале модель усредняет интенсивности для двух вариантов поля.

Состояния матчей плей-офф и известный счёт берутся из `match_observations`, куда поступают данные football-data.org. Подтверждённые пары и порядок матчей сервис принимает отдельным входом `officialDraws`. Если в сохранённом календаре уже известны соперники, а подтверждённые жеребьёвки для нужных стадий отсутствуют, `full sync` пишет `official-draw-required` и пропускает прогноз ЛЧ. Снимки ЛЧ, сохранённые без входных данных плей-офф, доступны для просмотра.

## Проверка в Preview

1. Убедитесь, что Vercel Preview для ветки и секрет `DATABASE_URL` выбранного GitHub Environment `development` указывают на одну preview-ветку Neon. `REVALIDATE_URL` должен указывать на `/api/revalidate` этого Preview. Проверьте настройки по [руководству синхронизации](SYNC.md#сброс-кеша-приложения).
2. В SQL Editor этой ветки проверьте наличие `public.season_forecasts`. Таблица появляется после миграции `0007_season_forecasts`, которую выполняет сборка Vercel.
3. Запустите **Sync football data** из ветки `feature/season-simulation` с окружением `development`, режимом `full`, турниром `PL` и `revalidate_only=false`. В логе ожидаются `Stored season forecast for PL` и `Application cache revalidated.` Запись `ok` в `sync_runs` подтверждает синхронизацию, а публикацию прогноза подтверждает отдельная запись в `season_forecasts`.
4. Сверьте ID из лога с последней записью АПЛ. Ожидаются `kind = league-table`, `runs = 10000` и время среза этого запуска.

   ```sql
   SELECT f.id, c.code, f.season, f.kind, f.model_version,
          f.data_cutoff, f.calculated_at, f.runs
   FROM public.season_forecasts AS f
   JOIN public.competitions AS c ON c.id = f.competition_id
   WHERE c.code = 'PL'
   ORDER BY f.season DESC, f.data_cutoff DESC, f.calculated_at DESC, f.id DESC
   LIMIT 1;
   ```

5. Откройте `/leagues/pl` в Preview и сверьте срез с SQL с учётом часового пояса. Проверьте прогресс, отмену и повторный запуск. После завершения сравните обе колонки и повторите SQL. При отсутствии параллельного `full sync` ID среза останется тем же.

Перед выпуском на production выполните порядок применения миграций и проверки расписания из [руководства синхронизации](SYNC.md#сброс-кеша-приложения).
